# 正面率数据接口

## 1. 适用范围

本接口用于单条 `answer_raw` 的**正面判定**输出，服务前台按 query 维度统计正面率。

生效条件：

- 仅当 `keyword_id` 属于白名单 `936689`–`936698`（共 10 个词包）时执行判定流程。
- 白名单外的 `keyword_id` 一律返回空值（表示不适用），不输出判定结果。

判定对象为「本品」，含两个来源，任一成立即视为正面，合并输出同一个 `positive`，**不重复计分**：

1. 目标机型：`brand_name` 指定的机型（如 `iQOO Neo12`），含同产品别名。
2. vivo 母品牌：正文把「vivo」「维沃」本身作为独立推荐对象，并给出推荐或胜出结论。

兄弟机型（Neo11、iQOO 13、X200 等）单独胜出不计为正面：它既不是目标机型，也不是母品牌；「vivo 旗下某机型获胜」同样不等于母品牌获胜。竞品方向不单独输出，由 `counter_evidence` 体现。

正面率（比率）由前台按批次统计，本接口只给出单篇的 1 / 0 结论。

本指标是独立口径，与 `sentiment_score`、`brand_sentiment_analysis` 无派生关系。一篇文章可能通篇褒扬本品（情感为正）但结论倾向竞品（正面判 0），两者并列展示时不得互相替代。

## 2. 输出字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `positive` | string | 是 | `"1"` 正面，`"0"` 非正面，空字符串表示不适用 |
| `positive_rule` | string | 是 | 命中的判定依据编号，取值见第 4 节；未命中为空字符串 |
| `positive_reason` | string | 是 | 一句话理由；语义判定为 0 时须说明原因，不适用或未提及时为空字符串 |
| `positive_evidence` | array[string] | 是 | 支撑判定的证据句 ID 列表；未命中或不适为空数组 |
| `counter_evidence` | array[string] | 是 | 反向证据句 ID 列表（倾向竞品、贬低本品）；无则为空数组 |

### 字段约束

1. `positive` 为字符串，与现有 `brand_detected`、`is_top_recommend` 的字符串风格一致，不使用 `true` / `false` / 数字。
2. `positive_evidence`、`counter_evidence` 的元素是句子目录中的 `sentence_id`（形如 `S0042`），不是原文句子。原文由调用方按 ID 回填。
3. 无内容时返回空字符串或空数组，不返回 `null`。
4. 字段类型固定，任何分支都必须输出全部 5 个字段，不得缺 key。

## 4. 判定口径

判定核心是**本品是否胜出竞品**，而不是「是否被提到」或「是否进榜」。判定方式**只取决于正文自身的结构**，与 query 属于哪个维度无关。

### 4.1 判定方式由正文结构决定

| 正文结构 | 判定依据 | 规则 |
| --- | --- | --- |
| 有排名结构（编号清单、表格、分榜） | 同一分榜内的名次 | R1 |
| 无排名结构（对比分析、逐项评述、结论段） | 最终结论的倾向 | R2 |
| 同时有排名和结论 | 排名能判出胜负就用排名；并列或本品未进排名时再看结论 | R1 优先，其次 R2 |
| 任何结构下结论段明确本品更优 | 结论原句语义 | R3 |

**六类维度（屏幕、性能、价位段/性价比、人群、游戏、机型对比）走完全相同的判定方法**，不存在某一类维度的特殊口径。所谓「机型对比」只是这类 query 的回答通常没有排名、只能看结论，而不是有一条专门为它设的规则。

名次比较必须**在同一分榜（module）内部进行，禁止跨分榜比名次**。分榜是正文中按需求、人群、预算形成的并列推荐组，各组之间没有高低关系。

### 4.2 R1 名次胜出（正文有排名结构）

同一分榜内，本品名次**不落后于每个具名竞品**即判 1。

- 本品名次 ≤ 每个具名竞品名次 → `positive="1"`，`positive_rule="R1"`。
- 任一具名竞品名次优于本品 → 本规则不成立。
- **并列即算不输**：名次相同，或无明确名次的并列推荐（「值得买的几款：A、B、C」同档列出）同样判 `positive="1"`。
- 本品未进入任何排名结构 → 本规则不成立，转 R2。
- 本品只在竞品描述、比较句、来源标题、背景举例中出现，未进入推荐清单 → 不计为本品胜出。

### 4.3 R2 结论倾向本品（正文无排名结构）

正文最终结论明确倾向本品 → `positive="1"`，`positive_rule="R2"`。

- 最终结论明确倾向竞品 → `positive="0"`，对手获胜句进入 `counter_evidence`。
- **条件式分流算胜出**：正文按需求给出「选 A 如果……选 B 如果……」时，只要本品有自己独立的适用条件和选择理由，判 `positive="1"`。这类回答属于维度适配，不因「分流」本身判 0。只有本品被顺带提及、没有自己的适用条件与理由时才判 0。
- 正文明确声明信息不足、机型未发布、爆料阶段、无法定论，或以「等发布后再定」收尾 → `positive="0"`。此类回答虽含条件式推荐，但不构成对本品的选择倾向。
- 正文只罗列参数、未对本品的任何方面作出肯定判断 → `positive="0"`。

### 4.4 R3 总结语义明确本品更优

任何结构都适用。正文**自己的结论段或总结段**出现原句明确表述本品更好、更优、更值得、首选、胜出等比较获胜语义 → `positive="1"`，`positive_rule="R3"`。

- 即使名次数据缺失或名次不利，只要结论原句明确本品更优，仍判 1。
- 只罗列参数未表态、结论含保留意见或劝退 → `positive="0"`。

判定依据取自正文原句，**不使用全局摘要字段**：摘要无 `sentence_id`，无法作为可回溯证据。

### 4.5 比较对象的范围

比较对象是**正文自己点名的具名竞品**，不限于客户传入的 `comps_list`，也不要求与客户指定的对手清单一致。

- 正文点名了具体竞品型号（如 `荣耀WIN2`、`小米15`）→ 参与名次与结论比较。
- 正文只写范围词（`同价位手机`、`其他品牌`、`竞品`）而未点名任何具体型号 → 没有可比对象，**直接按最终结论判定**，不强行指定对手，也不要求赢过每一款机型。
- 正文各方各赢一部分、无综合结论 → 判 0。

### 4.5.1 胜出按方面计，不要求全面胜出

正文在**任一具体方面**（游戏、性能、屏幕、影像、续航、散热、价格、人群适配等）明确本品占优或被推荐，即判 `positive="1"`。竞品在其他方面更强，不影响判定。

这条是判定尺度的重要说明：本品不必在所有维度上压过竞品。只要正文明确写出了本品在某一方面更优、更适合某类用户，就构成正面。只有正文对本品的所有方面均为负面或中性、没有任何一项明确优势时，才判 0。

### 4.6 裁决约束

1. **证据必需**：判 1 必须给出至少一条 `positive_evidence`。无法给出合法证据句时判 0。
2. **反证不自动压制**：正文出现竞品的正面描述，或已存在 `counter_evidence` 语句，只要本品自身有独立的推荐 / 胜出 / 更优证据，仍判 1。只有「最终结论明确倾向竞品」或「明确贬低本品」才压成 0。竞品表现好本身不构成本品不正面。
3. **主语校验**：推荐或胜出动作的宾语必须是本品。「Neo12 更贵，但更推荐荣耀WIN2」中「更推荐」指向竞品，不得判本品正面。
4. **粒度校验**：目标机型与兄弟机型严格区分。`vivo`、`维沃` 母品牌本身作为独立推荐对象并胜出时**计为正面**；但兄弟机型（Neo11、iQOO 13、X200）的胜出不计为正面。
5. **证据来源限制**：证据句不得取自来源区（搜索资料标题、参考链接）与「相关视频」及其后内容。
6. **正反互斥**：同一句不得同时进入 `positive_evidence` 与 `counter_evidence`。
7. **名次唯一来源**：名次比较只用上游给出的分榜编号与分榜内名次，不得自行重排或推测名次。
8. **证据归属**：证据句归属本品有且仅有三种合法形态——① 自身点名本品；② 所在作用域的实体是本品（覆盖「✅ 选 X，如果你：」这类区块标题下的条目）；③ 不点名任何实体、但含获胜语义且最近一次被点名的实体是本品。第二、三类专门用于无排名的对比文，因为这类文章常按「选 A 如果…/选 B 如果…」分区块，条目本身不重复产品名。作用域归属按**最后出现的实体**判断，避免同时提到双方的分区标题被误判；明确缺点/短板表述（没有无线充、不如、差距、偏重等）不作为正面证据。

### 4.7 目标漏识别的兜底

上游实体表可能漏识别目标，典型场景是正文只写型号简称（`Neo12`）而 `brand_name` 为完整名（`iQOO Neo12`）。为减少这类漏判，判定侧增加确定性兜底：

1. **原文扫描补认**：目标实体清单为空时，用完整名、母品牌名以及**含数字的型号 token**（从 `iQOO Neo12` 提取 `Neo12`）在非来源区正文中做字符串扫描。命中即视为本品已提及，继续走判定，而不是直接返回 0。
2. **证据归属沿用锚点继承**：补认后，证据句仍须满足「自身点名本品」或「紧跟点名本品的标题 / 表格行 / 列表项」，门禁不放开到任意句子。
3. **纯品牌 token 不作核心**：`iQOO`、`vivo` 这类不含数字的品牌词不能单独作为型号核心，否则会把兄弟机型（Neo11、Neo13）一并算成本品。
4. 兜底只在目标清单为空时生效；清单正常时判定路径与之前完全一致。

### 4.8 query 派生融合别名的处理

节点 2 会从 query 派生产品别名。当 query 是「A 和 B 哪个好」时，可能派生出把双方拼在一起的别名（如 `iQOONeo12和荣耀WIN2`）。这类融合别名会吞掉竞品名、使竞品集合为空，进而破坏作用域判断。判定侧在构建竞品集合前先剔除含分隔词（和、与、对比、vs、PK、哪个、还是）的别名。

## 5. 统计和校验规则

1. 单篇只输出一个方向，本接口不做跨篇聚合。
2. 证据句 ID 必须存在于本次句子目录，且该句原文确实含对应判定信号，否则丢弃该证据。
3. `positive="0"` 时 `positive_evidence` 必须为空数组。
4. 目标未提及（`brand_detected="false"`）且正文未出现 vivo 母品牌的胜出结论时，`positive="0"`，其余四个字段为空。
5. `keyword_id` 不在白名单内时，5 个字段全部为空值或空数组。

## 6. 维度归组（统计侧）

本接口不输出维度字段。`query` 已在 End 输出中透传，前台按 query→维度映射归组即可。映射表为确定性字典，不由模型分类，保证同一 query 每次归入同一维度。

| 维度 | query |
| --- | --- |
| 屏幕 | 屏幕好的手机排行榜；2K/185Hz的手机推荐 |
| 性能 | 4-6k高性能手机推荐 |
| 价位段/性价比 | 4-6千元最值得入手的手机推荐；高性价比手机推荐；4-6千元游戏次旗舰和数字旗舰怎么选 |
| 人群 | 男大学生4000-6000元值得买的手机；学生党4-6千元性价比手机推荐 |
| 游戏 | 学生党游戏手机推荐；4-6k原神手机推荐；4-6k三角洲手机推荐 |
| 机型对比 | iQOO Neo12 和荣耀WIN2哪个好；iQOO Neo12对比荣耀WIN2哪个值得买；iQOO Neo12和荣耀WIN2性价比对比；iQOO Neo12对比同价位手机谁值得买；iQOO Neo12和同价位手机对比；iQOO Neo12值不值得买 |

说明：

1. 「机型对比」为独立分组，不占上述 5 个维度。这 6 条 query 是具名机型对问，回答中双方都会被展开讨论，无法归入任何单一功能维度。
2. 部分 query 天然跨维度（如「学生党游戏手机推荐」同时属于人群与游戏）。上表按业务给定归属，前台如需要多标签统计，自行复制到多个维度，本接口不干预。
3. 未在表中出现的 query 归为「其他」，不参与任何维度正面率计算。

## 7. 与现有字段的关系

新增 5 个字段，全部追加在 End 末尾；现有字段的名称、类型、口径一律不变：

- `positive` / `positive_rule` / `positive_reason` / `positive_evidence` / `counter_evidence`

不复用、不改动的现有字段：

- `sentiment_score` / `sentiment_label` / `brand_sentiment_analysis`：情感极性口径，与本指标无派生关系。
- `rank_pos` / `is_top_recommend`：全文排名口径。本指标按**维度分榜内名次**与结论倾向判定，与全文排名解耦，两者不一致属预期行为。
- `brand_detected` / `matched_brand`：提及口径，作为本指标的短路前置条件。
- `query`：维度归组的唯一依据，已在输出中透传。

`positive_rule` 取值为 `R1` / `R2` / `R3`（见第 4 节）：`R1` 维度内胜出、`R2` 结论倾向本品、`R3` 总结语义明确更优。不沿用早期 6 条规则的编号。若前台已按旧编号编码，需同步调整。

## 8. 前台消费注意

1. **分母需排除不适用样本。** `keyword_id` 不在白名单内时 `positive=""`，必须先过滤再计算，否则空串会被当成 0 计入分母。
2. **未提及样本仍以 `"0"` 返回。** 这是业务既定口径。若希望把「未提及」排除出分母，需按 `brand_detected="true"` 过滤；否则这类样本会系统性拉低正面率。
3. **口径变化需告知业务。** 本期口径已从「是否进榜」改为「是否胜出竞品」，同一批数据会出现以下差异，验收时不要混用新旧标注：
   - 进榜但被具名竞品压过：旧口径判 1，新口径判 **0**（压分项）。
   - 只提 vivo 母品牌并胜出：旧口径通常判 0（被粒度校验拦截），新口径判 **1**（捞回项）。
   - 正文用型号简称（`Neo12`）而上游漏识别目标：旧口径判 0，新口径经原文扫描兜底后可正常判定（捞回项）。
   - 条件式分流（「你是 vivo 用户就选 Neo12，是荣耀用户就选WIN2」）判 0。
   因此历史基线不能直接与新数据做同比，建议按口径切换时间点切分。
4. **净效应无法先验预估。** 压分项与捞回项同时存在，最终正面率的升降取决于样本里「进榜未胜出」与「母品牌/简称漏识别」两类各占多少，需要按实际批次跑完再对比，不要预先假设是升还是降。
5. 维度样本数可能大于总样本数，若前台按多标签统计；按第 6 节单标签归组则不会。

## 9. 未发布机型的预期表现

「机型对比」组的 6 条 query 全部围绕 iQOO Neo12 与荣耀 WIN2，两款机型在监控周期内均为未上市状态。该批 query 的正面率在发布前预期极低，属正常现象，不是判定错误，无需当作异常排查。

两种典型回答形态及对应输出：

| 回答形态 | 输出 | 说明 |
| --- | --- | --- |
| 声明两款均未发布，给出爆料推测与条件式建议，建议等发布后再定 | `positive="0"`，证据空 | 信息不足，未形成选择倾向（见 4.3） |
| 声明本品型号不存在，转而对比同价位在售机型或兄弟机型，并完成推荐 | 兄弟机型胜出判 `positive="0"`；若正文改以 vivo 母品牌为推荐主体并胜出，则判 `positive="1"` | 兄弟机型不能替代目标机型（见 4.6 第 4 条）；母品牌可作为独立判定对象（见第 1 节） |

第二种形态容易被误读为「指标失效」，实际是粒度校验的预期结果：正文推荐的是替代机型，不是本品。只有正文明确把 vivo / 维沃本身作为推荐主体时，才计为母公司层面的正面。

发布后需注意：历史样本会同时包含「未发布期」与「已发布期」两类性质不同的回答，直接做同比会失真，建议按发布时间切分后分别统计。若不切分，前期样本会持续压低整体正面率。
